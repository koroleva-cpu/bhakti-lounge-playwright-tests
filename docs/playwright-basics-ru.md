# Playwright: коротко об основах

## Что происходит в тесте

`pytest-playwright` создаёт изолированный контекст браузера и передаёт тесту фикстуру `page`. Контекст похож на новое окно инкогнито: cookies и local storage одного теста не попадают в другой.

```python
def test_example(page):
    page.goto("https://example.com")
    page.get_by_role("link", name="More information").click()
    expect(page).to_have_url(re.compile(".*iana.org.*"))
```

Три части любого UI-теста: Arrange (подготовить состояние), Act (действие), Assert (проверить результат).

## Локаторы

Локатор — не найденный однажды HTML-элемент, а сохранённый способ его найти. Playwright заново разрешает локатор перед действием и автоматически ждёт, пока элемент появится и станет доступен.

Предпочтительный порядок:

1. `get_by_role(..., name=...)` — как элемент воспринимает пользователь и accessibility API.
2. `get_by_label(...)` — поля форм.
3. `get_by_text(...)` — устойчивый пользовательский текст.
4. `get_by_test_id(...)` — хороший контракт с разработчиками.
5. CSS/XPath — только когда семантического способа нет.

`time.sleep()` почти всегда является ошибкой: он либо замедляет тест, либо всё равно бывает недостаточным. Используй assertions и auto-waiting.

## Page Object

Классы в `pages/` прячут детали страницы: URL, локаторы и повторяющиеся действия. Тест описывает поведение пользователя, а не структуру HTML. Если верстка меняется, обычно достаточно исправить один page object.

Не нужно превращать Page Object в огромную копию сайта. Добавляй только то, что реально используется тестами.

## Фикстуры pytest

Фикстура — подготовленная зависимость теста. В `tests/conftest.py` создаются `base_url` и объекты страниц. Pytest подставляет их по имени аргумента:

```python
def test_home(home_page):
    home_page.open_page()
```

## Отладка

```powershell
pytest -m smoke --headed --slowmo 300
pytest tests/test_smoke.py::test_user_can_open_whats_on_from_home --headed
playwright show-trace test-results/<папка>/trace.zip
```

В проекте trace, screenshot и video сохраняются только при падении. Это даёт доказательства ошибки и не переполняет CI артефактами успешных запусков.

## Параллельный запуск

`pytest -n auto` распределяет тесты между процессами. Тесты должны быть независимыми: не полагаться на порядок запуска и не использовать общие изменяемые данные.

## Что тестировать дальше

- контракт API, если у проекта появится доступный backend;
- визуальные сравнения только для стабильных блоков;
- реальные формы на staging, а не на production;
- accessibility-проверки через axe;
- проверку внутренних ссылок отдельным быстрым HTTP-тестом.
